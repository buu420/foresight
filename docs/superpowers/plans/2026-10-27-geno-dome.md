# Geno Dome Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Make Geno Dome's visible puzzle controls, charge and droid movement readable and reachable.

**Architecture:** Add a scene-scoped `GenoDomeTargets` provider to the existing field source. Add `GenoDomeFeedback` observing the same coherent field capture and a small optional source observer callback. Native contacts and live map geometry remain authoritative.

**Tech Stack:** C#/.NET 9, existing x86 Reloaded-II hooks and Prism, xUnit, Python native-resource fixtures.

**Spec:** `docs/superpowers/specs/2026-10-27-geno-dome-design.md` (scope approved in chat).

## Global Constraints

- Native Confirm, timing, battles, locks and puzzle choices remain with the player/game.
- No hidden timer, puzzle combination, reward, save write, new native hook or second field poller.
- Scene and actor identity must match the supported native script evidence.
- Deploy a verified local 0.3.80 tester package; no public publication in this task.

## Review Focus

- Hidden electrical effects and missing state must not announce false discharge.
- Menus, disabled hooks, world travel and recycled engine pointers must not emit stale cues.
- Aliased terminal markers must not create duplicate targets or erase their real Confirm contact.
- Closed pods and unopened elevator doors must remain identifiable without invented walking exits.
- Escort routes must not require walking through a solid droid or expose the switch solution.
